# Public Assurance

This directory maps public technical propositions to the evidence classes, records, verification methods, temporal scope, and evidence ceilings that support them.

## Accepted records

- [Canonical Public Claim Registry](PUBLIC-CLAIM-REGISTRY.json) — machine-readable canonical propositions for realized Runtime standing, accepted-scope completion, Docker deployment readiness, established local Runtime operation, local Dashboard origin, model-independent Tier One operation, Runtime characterization, and Range Reactor maturity/qualification/performance.
- [Ecosystem Claim → Evidence Matrix](ECOSYSTEM-CLAIM-EVIDENCE-MATRIX.md) — technology-estate-wide claim/evidence map with estate lane, affirmative claim, accepted or established maturity, evidence class, public reference, verification method, and evidence scope.
- [EHCO AI-OS Claim → Evidence Matrix](CLAIM-EVIDENCE-MATRIX.md) — focused Tier One claim/evidence map.

## Assurance model

EHCOsystem tracks architecture, standing, source acceptance, artifact identity, declaration presence, test design, qualification, bounded observation, build/artifact evidence, release, deployment, production verification, Runtime evidence, and independent validation as distinct evidence classes.

Estate lane and maturity are independently tracked. The principal shared spine, research/foundation estates, and downstream governed application estate each retain component-specific maturity and evidence.

The foundational/shared EHCOsystem spine is substantially established. EHCO AI-OS is represented at its accepted realized baseline, Docker Portability at its established deployment-ready portability posture, and Range Reactor at its mature deterministic capability and physical qualification posture. `INSTANTIATED_EHCO_RUNTIME` remains the owner of Tier One Runtime authority and Runtime state.

For evidence-domain ownership, use the [Runtime, Repository, and Test-Estate Boundary](../architecture/runtime-repository-and-test-estate-boundary.md).
