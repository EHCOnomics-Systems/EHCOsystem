# EHCOsystem — An Instantiated AI Ecosystem

**Instantiated AI is the architectural category. EHCOsystem is EHCOnomics' Instantiated AI ecosystem.**

In this category, the computational conditions governing identity, authority, state, memory, source, scope, permissible action, evidence, release, and consequence are established independently of the intelligence they govern before consequential operation. Read the [Instantiated AI — Public Architecture Definition](INSTANTIATED-AI.md) for the category definition, standing concepts, dependency inversion, and qualification questions.

EHCOsystem expresses that category as a governed computational estate rather than a single model or application. **EHCO AI-OS is the realized Tier One Runtime** of EHCOsystem and provides its governing Runtime foundation. `EHCO_DOCKER_PORTABILITY` is the **PRIMARY_ACCESSIBLE_RUNTIME_PROJECTION** of that established Runtime lineage. The **current accepted working EHCO Dashboard baseline** is the principal presently established **Tier Three projection baseline** within the portability estate. **Downstream governed components** own distinct language, range/reasoning, retrieval/evidence, relationship, coordination, research, and domain-application functions.

The architecture is ownership-based: each major computational function has an identified owner, estate lane, maturity posture, evidence class, and lifecycle. Architecture, accepted source, qualification, build/artifact state, release, deployment, execution, application realization, Runtime participation, and currentness remain distinct evidence dimensions.

This ecosystem framing does not claim that every component has identical maturity, that every application is complete, or that every component is a current Runtime participant. Persistent software identity and application-local realization are separate from scoped Runtime participation, which requires owning Runtime evidence.

For first-read architecture views, see the [EHCOsystem Public Architecture Diagrams](diagrams/README.md). For the detailed distinction among Runtime, controlled source/test estates, and public evidence, use the canonical [Runtime, Repository, and Test-Estate Boundary](runtime-repository-and-test-estate-boundary.md).

## Current qualitative maturity posture

Current owning-source review supports a qualitative—not percentage-based—posture: the **foundational/shared EHCOsystem spine is substantially established**, while **remaining work is increasingly concentrated rather than foundational**.

The concentrated remaining work falls into four separately governed areas:

1. **bounded finalization/hardening** of established components and services;
2. **EHCO RAG implementation** progression;
3. **research/foundation reconciliation**; and
4. **continuing downstream governed domain/application expansion**.

This posture does not create one universal maturity label. The Runtime foundation, Language Model, Range Reactor, RAG, Prime, Agent Connect, research estates, and domain applications each retain their own source, qualification, artifact, release, deployment, execution, Runtime, and evidence state. No universal ecosystem completion percentage is asserted.

## Tier One — EHCO AI-OS

EHCO AI-OS is the realized Tier One Runtime and governing foundation of EHCOsystem. Its accepted standing baseline is **52/53**. It owns the Tier One relationships through which authority, scope, recognized state, transition, consequence, continuity, persistence, withholding, release, correction, recovery, and Runtime-originated proof acquire operational meaning.

Public source/control provenance is intentionally represented only at the minimum public-safe level necessary to distinguish source and repository state from instantiated Runtime authority. Exact private source locators and protected control paths are not part of this public architecture.

## Primary accessible Runtime projection and Tier Three baseline

### EHCO_DOCKER_PORTABILITY

`EHCO_DOCKER_PORTABILITY` is the **PRIMARY_ACCESSIBLE_RUNTIME_PROJECTION** of the established EHCO AI-OS hardened Runtime/root-image lineage. It is distinct from controlled source repositories, distinct from repository-local Docker or Compose test realizations, and is not an independent authority owner.

This is an architectural and lineage classification. It does not itself assert a present deployment, current host state, Runtime execution event, release, admission, binding, invocation, persistence effect, authority effect, or standing change. Those effects remain separate and require their applicable owning technical or Runtime evidence.

### EHCO Dashboard

The current accepted working EHCO Dashboard baseline is the principal presently established Tier Three projection baseline within the portability estate. The working baseline provides public-safe or controlled views over dashboard concerns such as overview, live trace, service/API state, health, readiness, rollback, authority interpretation, and settings.

The Dashboard remains a projection. Its working-baseline status does not establish present public hosting, public ingress, production operation, authoritative Runtime state, or dashboard authority. Runtime remains the parent truth owner where Runtime evidence is material.

## Principal shared downstream component spine

The principal shared spine contains reusable computational, evidence, relationship, and coordination owners. Membership in this lane does not imply equal maturity.

### EHCO Language Model — mature deterministic computational language

The EHCO Language Model is the deterministic computational-language component. Its architecture is single-path and zero-weight: language computation is performed through explicit computational structures and operators rather than learned-weight inference or delegation to an external language model.

Its controlled source estate establishes deterministic language processing, context/evidence binding, ambiguity/withholding, bounded reasoning, and component-service capabilities. Current accepted source has progressed through bounded staging and staging-verification reconciliation. That is stronger than the public snapshot alone, but it does not establish production verification, complete production operation, external benchmark leadership, independent certification, or universal language completeness.

A bounded portion of the actual test estate is publicly inspectable: seven exact synthetic fixtures covering 62 cases, with expected dispositions, a qualification-test index, manifest, and validation tooling. [Inspect the Language Model test evidence](../language-model/evidence/public-test-snapshot-v1/README.md).

### EHCO Range Reactor — mature deterministic range/reasoning owner

EHCO Range Reactor owns bounded deterministic range and reasoning computation. Its controlled source establishes reference/evaluation, verification/conformance, service, qualification, and container-oriented capability. Qualified accepted lineage is integrated into its current source posture.

No dedicated public Range Reactor evidence snapshot is published in this repository yet. The current source posture does not itself establish artifact release, deployment, production realization, Runtime effect, or independent certification. A future public evidence package requires its own disclosure, proof-ceiling, and verification operation.

### EHCO RAG — governed controlled implementation posture

EHCO RAG owns governed retrieval, context, source custody, provenance, and evidence-service functions. Its architecture separates retrieved evidence from application truth, model interpretation, organizational authority, and Runtime state.

RAG has an accepted control/specification baseline and a controlled implementation posture. Its continued implementation progression is one of the concentrated remaining-work areas; deployment, production realization, persistence, and Runtime participation are not inferred from architecture or source identity.

### EHCO Prime — advanced relationship-service source/control posture

EHCO Prime is the persistent individual-facing relationship service. Prime owns relationship continuity, intent reception and clarification, bounded proposals and capability requests, evidence/result intake, and individual-facing explanation.

Its current source/control hardening posture is advanced, but production build execution/artifact custody, external qualification, release, deployment, and Runtime participation remain separately evidenced. Prime is intentionally distinct from whichever model, provider, application, department, deployment, or session may be involved in an activity.

### EHCO Agent Connect — advanced coordination-service source/control posture

EHCO Agent Connect is the shared registry, discovery, compatibility, candidate-routing, health-observation, and route-evidence coordination service.

Its current source/control hardening posture is advanced, but production build execution/artifact custody, release, deployment, and Runtime participation remain separately evidenced. Registration, ranking, and candidate routing are coordination functions; they do not by themselves establish Runtime admission, binding, or invocation.
