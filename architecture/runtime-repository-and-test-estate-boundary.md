# Runtime, Repository, and Test-Estate Boundary

**EHCO AI-OS is the realized Tier One Runtime of EHCOsystem with accepted standing 52/53.**

This record maps the ownership and evidence domains across the Runtime, public repository, controlled source/test estates, downstream components and public evidence packets.

## Tier One Runtime domain

`INSTANTIATED_EHCO_RUNTIME` owns Runtime authority, standing, recognized state, transition, consequence, persistence, recovery, withholding, release, closure and Runtime truth.

## Public repository domain

The public `EHCOsystem` repository owns the approved public architecture, evidence, provenance, verification, diligence, navigation and publication record set.

## Controlled source and test estates

Controlled repositories and supporting estates own source, tests, compatibility contracts, packaging, container source, deployment-support assets and evidence-generation material. Their artifacts establish source identity, provenance, declarations, build/test behavior and other source-scoped propositions.

## Downstream component domain

Persistent downstream governed component identity records the software/application/service object and its capabilities. Scoped Runtime participation records a governed relationship with the instantiated Runtime. The applicable Runtime evidence owns admission, binding, invocation, disposition, authoritative consequence/persistence and canonical receipts for each corridor.

## Public Evidence Companion

Packets 00-08 preserve hash-bound public evidence with packet-specific scope.

### Packet 02 — Canonical Runtime Source Binding

Packet 02 binds an exact packet-time snapshot of runtime-support test/source artifacts to declared SHA-256 values. Its evidence class is **artifact identity, integrity and provenance**.

### Packets 03-05 — declarations and anchors

These packets bind exact artifact identities and named declarations/anchors. Their evidence class is **artifact identity + named construct presence**.

### Packet 06 — historical bounded observation

Packet 06 preserves a historical `local_live` test/observation window, direct observations, discrepancy records, additional behavioral evidence lanes, and manifest-verified package integrity.

Historical paths, container names, service names and port bindings are capture attributes associated with that observation window.

### Packet 08 — suite closure

Packet 08 binds dossier identity, prior packet manifests, verification statuses, receipts and suite-closure conditions.

## Status discipline

- **PROVEN** — established within an expressly identified proof scope.
- **BOUND_BY_PRIOR_PROOF** — preserved by an accepted proof root.
- **PRESENT_IN_REVISION** — present in the Git revision being interpreted.
- **CURRENT_RUNTIME_EVIDENCE_REQUIRED** — current Runtime evidence owns the proposition.
- **SOURCE_REVIEW_REQUIRED** — owning source review establishes the proposition.
- **CONTRADICTED_BY_VALID_PROOF** — displaced by accepted contradiction proof.

## Independent validation

Independent validation is its own evidence class and is established through an identified third-party record carrying method, scope, time and findings.
