# Proof and Status Classes

The EHCOsystem records distinct technical, evidentiary, source, build, integration, Runtime, deployment, and release states across the public estate.

## Core classes

### Instantiated and demonstrated

A governed relationship has been realized and evidenced through the EHCO system estate, including accepted Runtime controls, proof packets, source bindings, continuity controls, bounded captures, or Runtime-originated proof.

### Instantiated with protected implementation

The governed relationship is established in the controlled EHCO estate while implementation details remain protected from public disclosure.

### Source accepted

Canonical source identity, ownership, revision, merge, or repository-control state has been accepted through the governing source estate.

### Build verified

A bounded build, test, lint, typing, artifact, security, image, or workflow result has been verified for the identified source revision.

### Runtime admitted

A participant, component, or operation has entered the realized EHCO AI-OS Runtime through the governing admission and binding relationships.

### Runtime evidenced

EHCO AI-OS has produced authoritative operational state, receipt, proof, persistence, release, revocation, recovery, or consequence evidence for the governed operation.

### Publicly evidenced

Public-safe dossiers, proof packets, manifests, receipts, source bindings, captures, verification records, or release artifacts establish the stated public proof range.

### Publicly released

An artifact has been published through the canonical EHCOnomics public record with its version, manifest, checksum, and release identity.

### Separately controlled deployment or release

Production hosting, environment-specific deployment, public ingress, commercial activation, operational external release, and go-live remain governed status dimensions distinct from Runtime realization and standing.

## Evidence relationships

The public estate preserves the relationship among:

- source identity;
- accepted source state;
- build and test evidence;
- integration state;
- Runtime admission;
- Runtime-originated evidence;
- public proof;
- public release;
- production deployment and go-live authorization.

Each record carries the status established by its owning source, control, evidence, Runtime, deployment, or release record.

Moving private workstream state is not inferred from a dated public record. Packet-time identifiers preserve the snapshots they bind and do not become current source ownership or Runtime state.
