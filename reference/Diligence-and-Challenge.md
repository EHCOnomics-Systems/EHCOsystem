# Diligence and Challenge

## Deeper diligence
Use `ECOSYSTEM-DILIGENCE.md`, `TECHNICAL-DILIGENCE.md`, the public claim registry, and the claim/evidence matrix.

## Public-record correction
Use the repository's public documentation/evidence correction issue template for bounded public-record issues.

## Technical proof challenge
Use the technical challenge issue template for reproducibility, proof-protocol, evidence-routing, or public-verification concerns that can be discussed safely in public.

## Security / sensitive disclosure
Do not place vulnerabilities, credentials, private implementation details, protected repository/source topology, privileged endpoints, or protected infrastructure information in a public issue. Follow `SECURITY.md` and use an official private EHCOnomics contact channel.

## Effect discipline
A public correction, challenge, issue, comment, or reviewer observation does not by itself change Runtime state, Runtime authority, standing, deployment, or component lifecycle state.
