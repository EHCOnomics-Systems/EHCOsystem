# Diligence and Challenge

The public repository supports deeper review without turning public discussion into a substitute for technical evidence or controlled security reporting.

## Deeper technical review
Start with `ECOSYSTEM-DILIGENCE.md`, `TECHNICAL-DILIGENCE.md`, the public claim registry, and the claim-to-evidence matrix.

## Public-record corrections
Use the repository's public documentation/evidence correction issue template for bounded questions about architecture, evidence, navigation, provenance, or verification records.

## Technical proof challenges
Use the technical challenge issue template for reproducibility problems, proof-protocol questions, evidence-routing concerns, or public-verification issues that can safely be discussed in public.

## Security or sensitive disclosure
Do not publish vulnerabilities, credentials, private implementation details, protected repository or source topology, privileged endpoints, or protected infrastructure information in a public issue. Follow `SECURITY.md` and use an official private EHCOnomics contact channel.

## Effect of a public report
A correction, challenge, issue, comment, or reviewer observation does not by itself change Runtime state, Runtime authority, standing, deployment, or component lifecycle state.
