# Security and Responsible Disclosure

## Scope

This repository contains approved public architecture, evidence, provenance, research, verification, and publication materials. It is not the EHCO AI-OS Runtime and does not contain or hold Runtime authority, standing, authoritative state, consequence, persistence, release authority, or Runtime truth.

Controlled private repositories and runtime-support folders are bounded test, compatibility, source-comparison, packaging, deployment-support, and evidence-generation estates. They are not the Runtime.

## Public evidence boundary

Hash-preserved public evidence may retain bounded historical paths, container names, service names, local ports, repository identifiers, revision identifiers, or similar capture attributes where the applicable disclosure policy expressly permits retention.

Those attributes are not credentials, active instructions, current Runtime truth, current infrastructure locators, active endpoints, or deployment authorization. In particular, historical environment paths and port bindings in Packet 06 must not be treated as present network exposure.

## Reporting concerns

Do not publish suspected vulnerabilities, exposed secrets, private implementation details, or evidence that may affect operational systems in a public issue.

Report security concerns through an official EHCOnomics contact channel and include:

- a concise description of the concern;
- the affected public document or system reference;
- steps to reproduce, where appropriate;
- the potential impact;
- supporting evidence that can be shared safely.

## Prohibited public disclosure

Public material must not disclose:

- proprietary Runtime or participant implementation source;
- unapproved private repository names, internal file paths, commits, schemas, or control anchors;
- protected Runtime transition logic or Instantiation Bridge mechanics;
- credentials, tokens, private keys, privileged endpoints, or protected infrastructure details;
- private proof packets or controlled verification artifacts;
- current production topology, access instructions, or environment secrets.

## Automated checks

The repository workflow checks canonical dossier hashes, packet manifests, detached hashes, JSON syntax, suite closure, internal links, high-confidence credential patterns, required public boundary records, prohibited current-language patterns, and repository residue.

Automated checks reduce accidental disclosure and semantic-framing risk but do not replace human review, legal review, security review, or Runtime-originated proof.

## No security warranty

Public architecture, packet integrity, passing repository checks, source-artifact hashes, or bounded test results do not constitute a warranty that every implementation, integration, deployment, or production environment is secure.

Security claims are limited to the evidence, environment, time, and proof ceiling expressly stated by the applicable record.
