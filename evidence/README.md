# EHCO AI-OS Public Evidence Companion

This directory is the public landing surface for the EHCO AI-OS Public Evidence Companion associated with the **EHCO AI-OS Governed Operational Architecture — Public Edition v1.8**.

The companion preserves public evidence, provenance, standing projections, artifact bindings, named declarations, continuity records, historical observations, delivery records and suite verification.

**EHCO AI-OS is the realized Tier One Runtime with accepted standing 52/53 and accepted maturity `REALIZED / COMPLETE_IN_ACCEPTED_SCOPE`.** Runtime authority/current-state evidence and public evidence are distinct evidence domains with explicit owners.

The [Canonical Public Claim Registry](../assurance/PUBLIC-CLAIM-REGISTRY.json) is the machine-readable current interpretation layer for the final-closeout public representation. It binds the realized Runtime baseline, deployment-ready Docker portability, physically operated local Runtime, Dashboard local origin, external-model-disabled Tier One operating lineage, Runtime characterization, and Range Reactor maturity/qualification/performance propositions to their evidence classes and verification routes.

## Evidence classes

- **Runtime standing** — accepted standing records and their public projection.
- **Artifact identity/provenance** — files, hashes, manifests, revisions and packet-time bindings.
- **Declaration/anchor presence** — named construct presence in identified artifacts.
- **Bounded test/observation** — behavior for identified inputs, source, environment and time.
- **Packet integrity** — manifest, hash and suite closure verification.
- **Owning Docker/host execution evidence** — local service execution, image identity, endpoint behavior, networking, persistence, restart/relaunch and physical qualification observations.
- **Runtime-originated evidence** — authoritative Runtime state and effects.

## Published package

The canonical Version 1 package is [`evidence/public-evidence-companion/v1/`](public-evidence-companion/v1/) and contains Packets 00-08. The dossier PDF is bound inside Packet 00 and is also published through [`dossiers/`](../dossiers/).

Packets 00-08 retain their hash-preserved bytes and packet-time terminology. Active interpretation is provided by this landing page, the [Canonical Public Claim Registry](../assurance/PUBLIC-CLAIM-REGISTRY.json), and the [Runtime, Repository, and Test-Estate Boundary](../architecture/runtime-repository-and-test-estate-boundary.md).

## Packet map

### Packet 00 — Dossier Identity and Boundary
Binds the evidence companion to the exact public dossier identity.

### Packet 01 — Instantiated Standing
Projects the accepted **52/53** operational standing baseline in public-safe form.

### Packet 02 — Canonical Runtime Source Binding
Binds a packet-time set of runtime-support test/source artifacts to exact SHA-256 values. Evidence class: **artifact identity, integrity and provenance**.

### Packet 03 — Authority Enforcement
Records exact artifact identity and named authority-enforcement declarations/anchors. The historical `TIER1` identifier remains part of the hash-bound packet identity; active architecture uses **Tier One** terminology.

### Packet 04 — Runtime Packet and Continuity Anchors
Records artifact bindings and named packet, continuity and recursive-support declarations.

### Packet 05 — Proof, Collapse, Recovery, Release and Projection Anchors
Records artifact bindings and named proof, receipt, collapse, quarantine, freeze, recovery, release and projection constructs.

### Packet 06 — Observed Live Capture and Release Status
Preserves a historical bounded `local_live` test/observation window with direct observations, discrepancy records, additional behavioral evidence lanes and manifest-verified package integrity.

### Packet 07 — Public Boundaries and Delivery Status
Records architecture, standing, validation, projection and delivery relationships for the package.

### Packet 08 — Suite Verification and Closure
Verifies dossier identity, packet manifests, declared files, verification statuses, receipts and suite closure.
